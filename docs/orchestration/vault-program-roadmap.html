The fork: how the wrapper gets built

Operator ask: bring back the vault wrapper — upgradeable, universal, deployed per curated vault — and give the AI a wallet so it can deploy wrappers itself. Research memo (plan HTML, §4–§8) evaluated five shapes; the decision is recorded here.

CHOSEN — Option C, refined: beacon fleet + scoped AI deployer.
  • One universal wrapper implementation (any vetted ERC-4626 child).
  • One BeaconProxy per curated vault — cheaper than full-bytecode deploys; one beacon upgrade fixes the fleet.
  • Beacon owned by a TimelockController — 3-of-5 proposer, independent 2-of-3 canceller, ≥72h delay, no EOA.
  • Scoped AI deployer — deploy-only for already-allowlisted children; fee ≤ cap and caps enforced on-chain; gas only.
  • Child bound at initialization with no setter — single-purpose per vault, never re-pointable.
Rejected alternatives (recorded).
  • A · per-vault immutable wrapper — not universal; v3.0.0 already supersedes new deploys.
  • B · universal immutable — safe but no upgrade path; fixes require a new factory generation.
  • D · immutable core + upgradeable module — any module that influences share minting is custody-relevant; complexity without the trust win.
  • E · Morpho V2 Fee Wrapper — sanctioned, but V2-child-only and no high-water mark; stays available where a V2 child exists.
